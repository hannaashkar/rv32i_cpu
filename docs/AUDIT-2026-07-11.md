# Full-project audit — 2026-07-11

Method: 8-dimension multi-agent audit (RTL area, timing, Quartus settings,
build system, verification, software, docs, hygiene); every medium/high
finding adversarially verified against the actual files/reports by an
independent checker before inclusion. 65 raw findings → **36 confirmed**,
2 refuted (both were already-documented deliberate calls), 27 minor.

routing congestion at 96% LEs, A&S 53,200 LEs) — first time the per-entity

## 1. Strategy-changing discoveries (area)

The per-entity fitter table rewrites the shrink plan — there are TWO LE pigs,
not one, and together they are ~44% of the 10M50:

| Entity | Fitted LCs | Regs | Root cause |
|---|---|---|---|
| `gshare_bp:BP0` | **11,137** (fit.rpt:1440) | 5,926 | PHT-side read/update networks; PHT duplicated per read port |
| `ooo_prf:PRF0` | **10,947** (fit.rpt:1507) | 2,048 | 64×32 flop array, 6 async read ports (`rd_bypass`, ooo_prf.v:35-51), 3 write ports |
| `ooo_iq:IQ0` | 8,378 (historical D023 audit); **8,565 on D028** | 2,720 | 162-bit uop payload muxed 16:1 on 3 select ports; D028 top-two timing tree adds no state |
| flat `ooo_cpu` | 14,132 | — | incl. ~3k LEs of RAT checkpoints (8×192b + dual rat_after0/1 snapshot networks, ooo_cpu.v:438,601-611) |

  **already M9K** in this build (btb_target/btb_tag/btb_cond each show

  Design options must target the PHT read/update path — not the BTB.
  **DONE 2026-07-12 (D024, branch `gshare-m9k-pht`): Hanna picked A1;

  clean); OoO 19/19+40/40+25/25+25/25-vio. INV-G1 + INV-G2 self-checks
  armed. Board fit re-run to unblock the D023 demo.** See DECISIONS.md
  D024 / docs/GSHARE_SHRINK.md.
- [x] **[H] PRF → M9K via LVT replication — DONE D025.** 18 M9K banks +
  register LVT + folded reads + exact direct/shadow write-first bypass;
  **−8,895 LEs (43,609 → 34,714, 88% → 70%)**, IPC/cycles unchanged.
  See DECISIONS D025 and `docs/PRF_SHRINK.md`.
- [ ] **[H] IQ payload split** (wakeup array vs payload RAM). 111 of the
  162 uop bits (U_IMM/U_PC/U_PNPC/U_GHR/U_RS1A) are never consulted by

- [ ] **[H] Checkpoint slimming**: NCHKPT=4 (A/B the dispatch-stall cost),

- [ ] **[C] Async resets on pure payload arrays** (IQ `u[]`, ex_a/ex_b,
  wb_val, dr_* payload, SQ addr/data, rob_pc — ooo_iq.v:270-276,

## 2. Timing truths

- [x] **[C] Re-run fit + STA after the storage shrinks.** D025 reported
  **23.51 MHz Fmax** and +17.47 ns slack at the 16.67 MHz board clock.
  All top-20 paths crossed the ~41.9 ns `dmem → load bypass → store AGU →
  LQ oldest-match → rob_poison` chain.
- [x] **[H] LQ violation-path redesign — DONE D026.** The serial selector is
  now an exact 8→4→2→1 parallel match/min-age tree with the old scan retained
  as a simulation oracle. Fmax **23.51 → 25.10 MHz (+6.8%)**; LQ is absent
  from all top-20 paths. B015 was found and fixed by the new LQ unit model.
- [x] **[H] SQ forwarding/replay selector — DONE D027.** The serial
  youngest-older scan is now an exact parallel-candidate + balanced 8→4→2→1
  max-age tree. The old scan remains a live Verilator oracle. `sq-tb` passes
  300,087 cycles / 300,088 queries / 45,313 forwards / 90,252 conflicts /
  36,668 drains / 2,382 flushes, including mandatory occupancy 0–8,
  one/two/final-slot allocation, SB/SH/SW, multi-match, backpressure,
  flush/wrap, and winner-leaf 0–7 bins. SQ cost is 924 mapped combinational
  LEs / 596 registers and 1,024 total fitted LCs / 596 registers; no serial SQ
  node remains in the top 20. Both cores pass 20/20 directed+C, 40/40 rv32ui, 25/25
  base/system/NPU random, and 80/80 X-state runs; OoO also passes 25/25
  violation stress. Official reportable CoreMark is cycle-identical at
  1.422552 CoreMark/MHz, IPC 1.026, 506,197,207 cycles, and 519,453,600
  lockstep comparisons.
- [x] **[H] IQ port-1 select rewrite — D028 ROUTED + FULL GATES GREEN.**
  D027's 38.744 ns / 32-level top-20 family was the dependent
  `pick → clear → repick` path. D028 computes the oldest two ALU candidates in
  one balanced sorted-pair tree. INV-I1 retains the old topology as a live
  oracle; `iq-tb` passes 300,553 cycles / 74,571 complete-payload checks and
  every 3×16 winner leaf. Fmax is **27.02 MHz**, and the IQ is absent from all
  top-20 paths. Both cores pass 20/20 directed+C, 40/40 rv32ui, 25/25
  base/system/NPU random, and 80/80 X/reset; OoO additionally passes all three
  queue unit models and 25/25 violation stress, with zero lockstep divergence.
  Fresh coverage is 99.2% (1522/1534), 60 programs per core, zero failures;
  every D028 IQ addition is covered. Reportable 720-iteration CoreMark is
  cycle-exact to D027 at 1.422552 CoreMark/MHz, IPC 1.026, 506,197,207
  full-run cycles, and 519,453,600 lockstep comparisons, with official CRCs,
  reportable validation, and zero divergence. D028's merge gate is complete.
- [x] **[H] D029 load/JALR/redirect/PHT path — DEAD WB2 ARM CUT, FULL GATES
  GREEN.** The measured cone crossed the generic WB2 load-result EX bypass.
  Edge-by-edge scheduling/PRF proof showed that the load has already left WB
  before its earliest consumer reaches EX, so D029 removes only WB2 while
  retaining WB0/WB1. A permanent ROB-tagged exact source-use oracle models the
  former bypass priority and fatals if WB2 could win. Full verification and
  reportable CoreMark cover all six select-port/source bins with **zero WB2
  hits**; `load_wb_bypass.S` adds 24 focused checks. `hello.c` and CoreMark are
  cycle-exact. The old dmem family is absent from D029's top 20.
- [ ] **[H] True 2-stage issue-queue scheduler / readiness cut — NEW D029
  LIMITER.** D029's top-20 family is `rob_head → IQ readiness/operand select`,
  worst 31.517 ns. A registered scheduler remains a valid higher-frequency
  option, but its latency/IPC cost must be compared with a smaller relage/head
  dependency cut before changing the public issue timing.
- [x] **[H] D027 clock decision.** Keep the board at PLL /3 (16.67 MHz).
  D027 fits at 34,787 LEs / 95 M9Ks with Fmax 25.47 MHz, +20.745 ns setup at
  /3, +0.337 ns worst hold, every timing check positive, and zero
  unconstrained paths. That implies only **0.745 ns theoretical setup margin**
  at PLL /2, below the ≥3 ns slow-85C gate, so a /2 build was not attempted.
  Fresh /3 `.sof` and `.pof` images were assembled. Reconsider /2 after the IQ
  redesign.
- [x] **[H] D028 clock decision.** Keep PLL /3 again. D028 fits at 35,096 LEs
  with Fmax 27.02 MHz and +22.994 ns setup at /3; hold +0.372 ns, recovery
  +52.869 ns, removal +1.653 ns, every timing class positive, and zero
  unconstrained paths. Subtracting the 20 ns period change for PLL /2 leaves
  **+2.994 ns theoretical margin**, narrowly below the ≥3 ns gate. No D028
  /2 claim was made. A final post-RTL map+fit rerun exactly reproduced the
  documented numerical results; assembly
  at 22:44:32 completed with 0 errors / 0 warnings from MIF stamp `mlp`.
  Freshness-clean D028 MNIST `.sof`/`.pof` exist but remain unflashed, so
  hardware truth remains the earlier LED-walker/CFM image.
- [x] **[H] D029 clock decision — PROMOTE TO PLL /2 (25 MHz).** The post-cut
  PLL-/3 characterization reached Fmax 29.14 MHz and projected +5.678 ns at
  /2, clearing the predeclared gate. The actual PLL-/2 build then fit at
  **34,945/49,760 LEs (70%)**, restricted Fmax **31.29 MHz**, slow-85C setup
  **+8.045 ns**, hold **+0.339 ns**, recovery +34.440 ns, removal +1.506 ns,
  every timing class positive, and zero unconstrained paths. Assembly produced
  fresh MNIST `.sof`/`.pof` images. This is a verified 50% clock increase over
  /3 in the build evidence, but it remains unflashed; hardware truth is still
  the earlier 16.67 MHz OoO LED-walker/CFM image.
- [x] **[C] No fit/STA make target, no critical-path archiving** → added
  (`make synth-fit` / `synth-sta`, see Makefile).
